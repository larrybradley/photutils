****************************
What's New in Photutils 3.2?
****************************

Here we highlight some of the new functionality of the 3.2 release.
In addition to these changes, Photutils 3.2 includes several
smaller improvements and bug fixes, which are described in the full
:ref:`changelog`.

.. contents::
   :local:
   :depth: 2


Dependency Version Updates
==========================


New photutils.simulation Subpackage
===================================

A new :ref:`photutils.simulation <simulation>` subpackage provides
tools for making simulated images with known sources and for scoring
source-detection algorithms on them. It renders point sources and
extended sources such as galaxies convolved with a PSF, makes
controlled scenes such as close pairs and stars on bright galaxies,
adds white or correlated noise, assigns each source its optimal
signal-to-noise ratio, and measures completeness and false detections.
The :ref:`simulation-completeness` example in the user guide shows the
whole workflow.

The subpackage replaces the deprecated ``photutils.datasets`` tools
and ``photutils.psf.make_psf_model_image`` (see
:ref:`whatsnew-3.2-deprecations`).

Scene Generators
----------------

:func:`~photutils.simulation.make_model_params` has two new keywords.
``log_params`` samples the named parameters uniformly in log10, which
flux and size distributions in a completeness test need, and ``kind``
adds a column that labels the population, so tables of stars and
galaxies can be stacked and scored together.

Two new functions make controlled scenes for the hard cases of source
detection. :func:`~photutils.simulation.make_pair_params` makes close
pairs at set separations and flux ratios, and
:func:`~photutils.simulation.make_satellite_params` places sources
around host sources, such as faint stars on bright galaxies::

    >>> from photutils.simulation import (make_model_params,
    ...                                   make_pair_params,
    ...                                   make_satellite_params)
    >>> stars = make_model_params((512, 512), 100, flux=(3, 300),
    ...                           log_params=('flux',), kind='star',
    ...                           seed=1)
    >>> pairs = make_pair_params((512, 512), 20, (2, 6), flux=(50, 200),
    ...                          flux_ratio=(0.1, 1), kind='pair', seed=2)
    >>> hosts = make_model_params((512, 512), 5, r_eff=(10, 20),
    ...                           min_separation=100, border_size=60,
    ...                           seed=3)
    >>> on_hosts = make_satellite_params(hosts, 10, (0.5, 2.5),
    ...                                  radius_unit='r_eff',
    ...                                  flux=(5, 300), kind='star_on_gal',
    ...                                  seed=4)

Populations that will be stacked need different ``seed`` values, or
their positions are correlated.

Correlated Noise
----------------

:func:`~photutils.simulation.make_noise_image` has a new ``kernel``
keyword that correlates Gaussian noise by convolving it with a kernel,
while keeping the requested per-pixel standard deviation. This mimics
resampled images such as mosaics, where the per-pixel error understates
the noise on larger scales. The new
:func:`~photutils.simulation.noise_correlation_factor` function returns
the factor by which a kernel raises the noise on scales larger than the
kernel::

    >>> from astropy.convolution import Gaussian2DKernel
    >>> from photutils.simulation import (make_noise_image,
    ...                                   noise_correlation_factor)
    >>> kernel = Gaussian2DKernel(1.5)
    >>> noise = make_noise_image((512, 512), mean=0.0, stddev=1.0,
    ...                          kernel=kernel, seed=0)
    >>> factor = noise_correlation_factor(kernel)

Sersic Sources and Convolved Rendering
--------------------------------------

The new :class:`~photutils.simulation.SersicSource` model is a Sersic
profile parameterized by its total flux, and
:func:`~photutils.simulation.make_convolved_model_image` renders sources
such as galaxies convolved with a PSF model that is integrated over the
pixels, such as an ePSF or a model whose name ends in ``PRF``. The new
:func:`~photutils.simulation.optimal_snr` function returns the
matched-filter signal-to-noise ratio of each source, calculated from the
same rendering and an image of the pixel errors::

    >>> import numpy as np
    >>> from photutils.psf import CircularGaussianPRF
    >>> from photutils.simulation import (SersicSource,
    ...                                   make_convolved_model_image,
    ...                                   make_model_params, optimal_snr)
    >>> shape = (200, 200)
    >>> params = make_model_params(shape, 20, min_separation=20,
    ...                            border_size=10, flux=(500, 1000),
    ...                            r_eff=(1.5, 4), n=(0.5, 4),
    ...                            ellip=(0, 0.6), theta=(0, 3.14), seed=0)
    >>> psf_model = CircularGaussianPRF(fwhm=3.0)
    >>> image = make_convolved_model_image(shape, SersicSource(), params,
    ...                                    psf_model)
    >>> error = np.full(shape, 0.5)
    >>> snr = optimal_snr(SersicSource(), params, error, psf_model=psf_model)

Scoring Source Detection
------------------------

Four new functions score a detection algorithm against the input
sources of a simulated image.
:func:`~photutils.simulation.match_segments` matches a segmentation
image and :func:`~photutils.simulation.match_sources` matches a source
list (for example from a star finder or PSF photometry). Both credit
each segment or detection to one input source only, the one with the
largest priority (by default the flux), so a blend detects only one of
its sources.
:func:`~photutils.simulation.completeness` gives the fraction detected
in bins of a source property with Wilson score intervals, and
:func:`~photutils.simulation.false_detection_rate` counts detections on
pure-noise images. The :ref:`simulation-completeness` example in the
user guide uses all four.

New Deprecations
----------------

The ``photutils.datasets`` subpackage is deprecated and will be removed
in version 4.0. For the functions that make simulated data, use the
functions of the same name in :ref:`photutils.simulation <simulation>`
instead. Their optional arguments are keyword-only, so any optional
argument must be passed by name. The ``load_*`` functions and
``get_path`` have no replacement and keep their existing deprecation.
Update your code::

    # Old (deprecated)
    from photutils.datasets import make_noise_image
    noise = make_noise_image((100, 100), mean=5, stddev=2, seed=123)

    # New
    from photutils.simulation import make_noise_image
    noise = make_noise_image((100, 100), mean=5, stddev=2, seed=123)

The ``n_nodes`` keyword of
:func:`~photutils.simulation.make_model_image` replaces the
``discretize_method`` and ``discretize_oversample`` keywords of the
deprecated ``photutils.datasets.make_model_image``.

The ``photutils.psf.make_psf_model_image`` function is deprecated and
will be removed in version 4.0. Use
:func:`~photutils.simulation.make_psf_model_image` instead::

    # Old (deprecated)
    from photutils.psf import make_psf_model_image
    data, params = make_psf_model_image((100, 100), psf_model, 10,
                                        min_separation=5, seed=123)

    # New
    from photutils.simulation import make_psf_model_image
    data, params = make_psf_model_image((100, 100), psf_model, 10,
                                        min_separation=5, seed=123)

The new function raises a ``TypeError`` for a PSF model whose name
ends in ``PSF``, such as ``GaussianPSF``, except for an ``ImagePSF``,
because the model is not integrated over the pixels. Use a model whose
name ends in ``PRF`` or an ePSF instead.
